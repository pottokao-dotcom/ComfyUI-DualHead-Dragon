輸入圖片
參考圖張數最多 10 張（image_1…image_10）。comfy 節點的 autogrow 開到 16 槽，但官方只保證 10。範例：6 張人像合團照。README · 範本 note · nodes_qwen.py部分1、2 張出圖跟官方一致；3–10 張還沒測。
圖的角色image_1＝編輯目標（canvas），其餘是參考。prompt 用 <image1>…<image10> 指稱；順序＝模型讀取順序（block-causal，後面的區塊看得到前面的）。範本 note · diffusers doc已驗證模板字串和 token 序列跟官方逐 token 一致。
圖片縮放resolution＝總像素預算（不是邊長），保持比例，寬高各自取整到 32；預設 1024；0＝不縮放、只取整到 32；模型支援到 2048。同一次縮放同時餵視覺塔和 VAE。nodes_qwen.py · diffusers已驗證res 1024 和 0 都測過，視覺 token 數跟官方一致（1014／988）。
Alpha 通道視覺塔看「alpha 疊在白底上」的 RGB；VAE 保留 4 通道 RGBA。nodes_qwen.py · diffusers已驗證繼承官方節點後，疊白底由官方程式碼處理；用 RGBA 關羽做 edit，結果跟官方一致。
視覺 tokenpatch 16 × merge 2 → 32×32 px 一個 token（1 MP ≈ 1024 token）。comfy 的像素上下限：3,136 到 12,845,056；deepstack 注入第 8、16、24 層。qwen3vl.py · qwen_vl.py已驗證llama.cpp mtmd 上下限是 8,192 到 16.7M，一般尺寸跟官方一樣。
TE 編碼
模板system「Comprehend and analyze the provided prompt.」；有圖時在 user 開頭插 <imageN><|vision_start|><|image_pad|><|vision_end|>，多張用空白隔開；不加 think 區塊。qwen_image21.py · diffusers已驗證
取哪一層hidden_states[-1]，還沒過 final RMSNorm（transformers 4.57 的行為；diffusers 另外用 hook 強制成這樣）。qwen_image21.py · diffusers已驗證llama.cpp 給的是過了 norm 的值，除以 output_norm.weight 後等價；T2I cos 0.976 / 0.984。
裁切／slots丟掉 system turn（第二個 <|im_start|> 之前）。有接 VAE：視覺 token 從輸出拿掉，改記 image_slots，由 DiT 在該位置插入參考 latent。沒接 VAE：保留視覺 token，只靠 TE 帶圖的資訊。qwen_image21.py已驗證有 VAE：slots 一致，圖後文字 cos 0.97（Q4）／0.999（Q8）。沒 VAE：能跑，但對精度敏感，換紅背景成功率官方 3/3、Q4 1/3、Q8＋f32 mmproj 2/3。
圖的資訊有沒有進去文字 token 在 forward 時看過圖，隱狀態帶有圖的資訊。—已驗證換圖會讓文字隱狀態改變 25–30%；我們的變化方向跟官方一致，cos 0.82–0.87（Q4）。
負面 prompt也帶著同一組圖編碼；只有 cfg > 1 才會用到（true CFG，每步計算量變兩倍）。官方預設 cfg 1。nodes_qwen.py · diffusers已驗證由官方節點處理。
VAE／DiT 端
參考 latentvae.encode(縮放後的圖) → 放進 conditioning 的 reference_latents（positive 和 negative 都要）。VAE 空間壓縮 16 倍、64 通道；1 MP 的參考圖＝4,096 個 latent token。nodes_qwen.py · diffusers已驗證由官方節點處理；edit 單圖、雙圖、去背的 A/B 都跟官方一致。
輸出畫布comfy：依 image_1 縮放後的尺寸吐空 latent。diffusers：沒指定寬高時依最後一張圖的比例。尺寸要是 32 的倍數。nodes_qwen.py · diffusers已實作canvas=encoder 時照官方（image_1）；canvas=rewrite 時依 PE 的 ratio_follow／wh_ratio 決定。

PE 改寫（雙頭龍要取代的部分）
改寫 T2I詳見下方 PE 官方設定。輸出 {"rewritten_prompt","wh_ratio"}。prompt_rewrite/能跑JSON 解析成功、wh_ratio 有套用到畫布。品質是裸 8B 的水準：約 220 字（官方要 400–500），英文裡混中文。要靠 LoRA 補。
改寫 I2IPE 看著圖寫出帶 <imageN> 的指令；輸出 {"rewritten_prompt","wh_ratio","ratio_follow"}。prompt_rewrite/能跑單圖、雙圖都能跑，JSON 解析也成功。裸 8B 會違反語言規則（英文指令卻回中文），雙圖時幾乎照抄原文。要靠 LoRA 補。
圖只讀一次（雙頭龍的設計要求）視覺塔的輸出（含 deepstack）跟位置無關，可以快取起來，讓改寫和編碼兩段共用；VAE latent 也只算一次。設計已驗證視覺輸出依圖片內容快取。i2i 單圖：編碼 1 次、命中 2 次（PE 看圖編一次，正面和負面直接用快取）；雙圖：編碼 2 次、命中 4 次。超過 1.1 MP 時 PE 會另外讀一份縮圖。
LoRA 切換（雙頭龍）生成時 scale＝1，編碼時 scale＝0，TE 永遠是 base。設計已實作・未測生成時掛上（llama_set_adapters_lora），編碼前卸下。節點內還沒實測。2026-09-26 在 gx10 用 llama-server 載 v2 LoRA（qi21_pe_master_lora_v2-f16.gguf），每個請求用 lora 欄位切換 scale 1／0：能跑，JSON 輸出正常。
生成加速 EAGLE-3（雙頭龍）PE 生成時掛一顆 EAGLE-3 草稿頭，一層，約 0.4B 參數，bf16 799 MB。只加速自回歸生成；TE 編碼只跑一次 forward、不生成，用不到草稿頭，也不受它影響。設計 · llama.cpp docs/speculative.md架構已驗證・頭要自己練只在節點裡做、不改 llama.cpp 的原型已跑通（tools/spec_proto/）。現成的頭太弱（每輪約 2，跟它們自己回報的一致），攝影擴寫反而變慢。目標：頭約 400 MB、擴寫 3 倍速。細節見「差異與待決」的「生成加速」列，以及 docs/DUAL_HEAD_METHOD.md。
VRAM 一份／12 GB（雙頭龍）一顆 8B 同時當 TE 和 PE；整套要塞進 12 GB。設計部分節點已經是單一進程、權重載一次；VRAM 還沒實際量過。

差異與待決 OPEN

事項內容建議
輸出畫布跟哪張圖comfy 跟 image_1，diffusers 跟最後一張（image[-1]）。官方 PE 用 ratio_follow 明確指定跟哪張。節點跟 comfy 一樣走 image_1；rewrite=on 時改依 ratio_follow／wh_ratio 決定。
PE 要不要開 thinking官方開著，預算 16k–24k token，在 12 GB 卡上會很慢。blackhole 那輪為了避免 JSON 被截斷而關掉了。待決：訓練 LoRA 時用什麼格式，推論就照同樣格式。
圖只讀一次的尺寸衝突PE 讀圖上限 1 MP 且不取整；TE 依 resolution（預設 1024² 取整到 32，範本用 0＝原尺寸）。resolution ≤ 1024 時共用同一份 32 取整的圖（偏差 < 3%）；更大時 PE 另外讀一份 ≤1 MP 的縮圖。
沒接 VAE 的路徑官方節點允許有圖但沒接 VAE（保留視覺 token）；三個官方範本都有接 VAE。先支援有 VAE 的版本；沒 VAE 的版本需要自己 decode 視覺 token 才拿得到隱狀態。
生成加速（MTP／EAGLE-3）瓶頸在 PE 逐 token 生成（t2i 約 360 token／10 s；LoRA 蒸餾版輸出是英文、約 800 token、格式固定，很適合 speculative）。我們的 8B、原版 Qwen3-VL-8B、官方 PE（Qwen3.5 9B）都沒有 MTP 權重，所以改用外掛草稿頭。

選型（2026-09-26）：HF 上現成的頭，bf16 大小：
・EAGLE-3：Qwen3-4B 437 MB；Qwen3-VL-8B 799 MB（taobao-mnn、AQ-MedAI）
・DFlash：Qwen3-4B 1,075 MB（z-lab）；8B 只有純文字 Qwen3-8B 版，2,097 MB，跟 VL-8B 權重不同，等於要自己練
EAGLE-3 比較省，大約是 DFlash 的四成。llama.cpp 兩種都支援（--spec-type draft-eagle3／draft-dflash），節點自帶的 4df29be 也有 eagle3.cpp、dflash.cpp。但實作寫在 common/speculative.cpp，不在 llama.h，vendored bindings 要多包一層才叫得到。
